# Crime-Fin

> **금융 범죄 예방 및 대응을 위한 웹 플랫폼**

## 프로젝트 개요

Crime-Fin은 보이스피싱, 스미싱 등 금융 범죄를 예방하고 대응하기 위한 웹 플랫폼입니다.

사용자는 금융 범죄 관련 정보를 조회하고, AI 분석 결과를 확인할 수 있으며, 주변 은행과 경찰서를 검색하거나 금융 데이터를 시각화한 대시보드를 통해 자신의 금융 활동을 확인할 수 있습니다.

저는 **사용자 인증 기능과 관련된 일부 백엔드 API를 구현했으며, Vue 기반 프론트엔드 개발과 대시보드 화면 구현을 담당**했습니다.

특히 프로젝트 종료 직전 발생한 대시보드 데이터 출력 문제를 해결하며 데이터 흐름과 화면 렌더링 과정을 분석하는 경험을 할 수 있었습니다.

# 시스템 구성

```
Vue Client

      │

      ▼

Spring Server

      │

      ▼

MyBatis

      │

      ▼
```

프론트엔드는 Vue를 기반으로 구현했고, 백엔드는 Spring과 MyBatis를 이용하여 REST API를 제공했습니다.

사용자 인증과 데이터 조회는 Oracle Database를 기반으로 처리했으며, 일부 기능은 AI 분석 서버와 연동하여 결과를 제공했습니다.

# 기술 선택

## Spring + MyBatis

프로젝트에서는 MyBatis를 활용하여 Oracle Database와 연동했습니다.

SQL을 직접 작성하면서 데이터 조회 과정을 명확하게 확인할 수 있었고, Oracle 기반 데이터 처리를 경험할 수 있었습니다.

---

## Vue.js

당시 프로젝트에서는 Vue를 사용했습니다.

비교적 간단한 문법과 컴포넌트 구조 덕분에 빠르게 화면을 구현할 수 있었고, 컴포넌트 기반 개발 방식을 경험할 수 있었습니다.

이후 프로젝트에서는 React를 선택했지만, 프레임워크보다 컴포넌트 설계와 상태 관리 방식이 더 중요하다는 점을 배울 수 있었습니다.

---

## Kakao Map API

사용자의 위치를 기반으로 주변 은행과 경찰서를 조회하는 기능을 구현했습니다.

외부 API를 활용하여 지도 위에 기관 정보를 표시하고, 금융 범죄 발생 시 빠르게 대응할 수 있도록 사용자 편의성을 높였습니다.

# 핵심 구현

## 금융 데이터 대시보드

사용자의 금융 데이터를 시각화하여 입출금 현황과 거래 추이를 확인할 수 있는 화면을 구현했습니다.

기간별 거래 내역과 계좌 분포를 차트 형태로 표현하여 데이터를 직관적으로 확인할 수 있도록 구성했습니다.

---

## 금융 범죄 예방 콘텐츠

금융 범죄 대응 매뉴얼과 체크리스트를 조회할 수 있는 기능을 구현했습니다.

또한 사용자가 퀴즈 형식으로 금융 범죄 대응 방법을 학습할 수 있도록 피싱 예방 문답 게임 화면도 개발했습니다.

---

# 트러블 슈팅

## 대시보드 데이터가 정상적으로 출력되지 않는 문제

프로젝트 마무리 단계에서 대시보드의 거래 추이 그래프와 계좌 현황 데이터가 정상적으로 표시되지 않는 문제가 발생했습니다.

프로젝트 종료를 일주일 정도 앞둔 상황이었기 때문에 제한된 시간 안에 원인을 찾아야 했습니다.

먼저 API 응답 데이터를 확인하여 서버에서 전달되는 데이터가 정상인지 확인했고, 이후 Vue 컴포넌트의 데이터 바인딩과 차트에 전달되는 데이터를 순차적으로 확인했습니다.

데이터 전달 과정과 화면 렌더링 과정을 하나씩 추적하면서 문제가 발생한 지점을 수정했고, 프로젝트 종료 전에 정상적으로 데이터를 출력할 수 있었습니다.

이 경험을 통해 문제가 발생했을 때 단순히 코드를 수정하기보다 **데이터가 어디에서 생성되고 어디에서 사용되는지 흐름을 추적하는 과정이 중요하다**는 점을 배웠습니다.

# 프로젝트를 통해 배운 점

Crime-Fin은 처음으로 실무와 유사한 방식으로 협업을 경험한 프로젝트였습니다.

Spring과 MyBatis를 활용한 백엔드 개발뿐 아니라 Vue 기반 프론트엔드 개발도 함께 수행하면서 프론트엔드와 백엔드가 데이터를 주고받는 과정을 이해할 수 있었습니다.

무엇보다 프로젝트 막바지에 발생한 대시보드 문제를 해결하면서 기능 구현보다 **문제를 끝까지 추적하고 해결하는 과정이 개발자의 중요한 역량**이라는 점을 경험했습니다.

이후 프로젝트에서는 구현을 시작하기 전에 데이터 구조와 흐름을 먼저 설계하려고 노력하고 있으며, 문제가 발생했을 때도 로그와 데이터 흐름을 기반으로 원인을 분석하는 습관을 갖게 되었습니다.
